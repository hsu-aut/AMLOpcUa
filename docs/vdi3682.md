# VDI 3682 and OPC UA

A Formalised Process Description (VDI/VDE 3682) and an OPC UA model can live
in the same AML document, for instance the process from the FPB plugin and the
devices from an OPC UA import or a running server. **Link VDI 3682** connects
them:

| From (VDI 3682) | To (OPC UA) | Attribute |
|---|---|---|
| TechnicalResource | the Object that represents the same resource | `refOpcUaObject` |
| ProcessOperator | the Method whose call executes the process | `refOpcUaMethod` |

VDI 3682 elements are recognised by a class path or role ending in
`FPD_TechnicalResource` or `FPD_ProcessOperator`, which is how the FPB mapper
writes them. OPC UA elements are elements typed by an Annex A class; a
ProcessOperator may only point to a method, a TechnicalResource only to an
object.

## How the link is written

Both attributes are object references in the sense of the AutomationML object
reference attribute types (Drath, AutomationML e.V., version 1.1.1-beta): type
`xs:IDREF`, value the ID of the referenced element. They are derived from the
unspecific `refObj`, as that library intends for relationships of their own:

```
AMLOpcUa_ReferenceAttributeTypeLib
  refOpcUaObject   RefAttributeType = AutomationML_ObjectReferences_AttributeTypeLib/refObj
  refOpcUaMethod   RefAttributeType = AutomationML_ObjectReferences_AttributeTypeLib/refObj
```

Both libraries are added to the document on the first link. The object
reference library is embedded unmodified, because the AutomationML Editor does
not load libraries through a file reference. A link whose target was removed
is reported by the check as UA008.

## Open question

A TechnicalResource and the OPC UA object of the same device are arguably the
same logical object seen in two aspects. The object reference library has
`refBaseObj` for that (aspect to base). It is not used here because it asks
which side is the base: the process view, the communication view, or a third
hierarchy such as the plant structure that both refer to. That is a modelling
decision of the document, and of the reference framework itself, which is
still a beta. `refOpcUaObject` states the relation without taking a side and
can later be replaced by, or complemented with, `refBaseObj`/`refAspectObj`.
